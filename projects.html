8 Project readiness checklist

Written in yellow marker beside the board — "Every project should have…". It is the strongest piece of process on the whole board, so it gets its own section.

Every project should have:
  1. A vision & mission
  2. A full user story
  3. A full breakdown structure & documented testbeds
  4. Backend revision criteria
  5. A well-written readme file
  6. Deployment criteria & server specification
  7. Notes for improvements
  8. Tasks contribution for that project

And it should answer the question

For how long will this project be needed?
For how long will we work on this project?
Worth deciding as a team: is this checklist a gate (no project starts without it) or a target to grow into? That changes how the scoring page should treat a project that cannot meet it yet.
